# 信息流编写

## 中文入口与菜单

用户输入「-信息流编写」「信息流编写」或「$信息流编写」时使用本技能。若同时提供任务或素材，直接进入对应流程；仅输入命令时显示菜单：

1. 新客户需求采集
2. 根据 brief 编写脚本
3. 优化已有文案
4. 文案风险自检
5. 打开需求采集表单

请用户回复选项并提供已有资料，不重复索取已提供的信息。表单预填品牌及清单示例仅为演示，不是新客户的真实信息。交付文件写入当前工作区 outputs/，无文件需求可直接在聊天交付。规则检查只是文案自检，不保证平台审核或投放效果。


面向本地服务业客户（全屋定制、家居、装修、建材等）的抖音信息流获客文案生产线。核心方法：**「城市业主痛点钩子（前 3 秒）→ 出镜人 IP 口语讲 3–4 个实力点（中间）→ 私信留资（结尾）」**，按三场景映射批量产出可直接拍摄的成套脚本。

## 触发场景

- 用户带来一个新客户/新品牌，要求批量产出信息流获客文案
- 用户提交已填写的调查清单或 brief，要求按其产出脚本
- 用户要求优化 / 合规检查 / 批量复制已有的信息流文案结构

## 工作流（四步）

### 第 1 步 · 需求采集

读取 `references/intake-checklist.md`（客户情况调查清单，共 7 组）。判断用户是否已提供足够信息：

- **信息不全**：将清单以文档形式交付给用户转发客户填写；或当面按清单分层提问（每组 1–2 问、共 4–8 问一次问完，关键决策点给出 A/B/C 选项，不追问过细）。必采项：品牌与主体、出镜人 IP、实力背书、痛点、三场景映射（痛点→拍摄地→结尾动作）、转化动作。引流款与投放预算可选。
- **用户想自助生成**：引导其打开 `assets/需求采集表单.html`，填完点「生成」即可得到完整 brief（表单已内置通用模板要求）。

### 第 2 步 · 组装 brief

将清单答案组装成一份完整 brief：品牌信息 + 出镜人 + 实力点素材库（只用客户确认的素材，缺项标注「待确认」，不现编）+ 痛点池 + 三场景映射 + 转化与投放 + 通用模板要求（见 `references/copy-rules.md` 固定段落）。展示 brief 让用户确认后再进入产出。

### 第 3 步 · 批量产出脚本

读取 `references/copy-rules.md`，按三段式逐条产出。默认 15 条（三场景各 5 条），数量按用户要求调整。每条须含：开头钩子、中间买点阐述与过渡、结尾私信引导三段。产出自检标准见 copy-rules 的「调性要求」与「合规红线」。

### 第 4 步 · 合规自检与交付

- 按 `references/copy-rules.md` 的合规红线逐条扫描全部口播文案（禁用词零命中才可标注「安全出稿」；「免费」类表述按用户原意保留并附卡审替换说法）。
- 交付拼接文档（HTML 表格）：序号 / 场景 / 开头 / 中间 / 结尾 五列，附拍摄提示与「待客户确认项」（数量宣称、计价单位、认证凭据等），并提供一键复制纯文案按钮。
- 数字、年限、品牌名、认证等表述须与客户提供的凭据一致；无凭据的数量宣称（如「上千家案例」）不写入文案，并在待确认项中提示。

## 注意事项

1. **不现编素材**：实力点只取自客户确认的清单内容；信息不足时如实标注，不虚构数字、认证、案例数量。
2. **活人感优先**：用户（叶老师）明确要求文案「不机械、无 AI 味、小白能听懂但显专业」——具体写法见 copy-rules。
3. **增量交付**：先交 3 条样稿供客户校准语气，确认后再补齐全量。
4. **最终决策权在用户**：以「建议 / 推荐」表述，不替客户决定是否发布。
